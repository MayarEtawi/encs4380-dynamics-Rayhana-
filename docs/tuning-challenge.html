QUICK REFERENCE

How to read your results

01 Overshoot

The largest amount the output rises above the setpoint.

OS =max(0, ypeak − r)r× 100%
For this unit step from zero to one.

02 Settling time

The earliest time after which the output stays within ±2% of the setpoint.

At least one final second must remain in the band.

03 Steady-state error

The remaining difference between the target and the settled output.

ess = |r − yss|r × 100%
Estimated from the final second. Oscillating or drifting tails do not pass.
Model, numerical method & metric definitions

Random plant families and parameter ranges follow Homework 1 Module 4: first order Kτs + 1, K ∈ [0.8, 3.2], τ ∈ [0.45, 2.2]; or second order ωₙ²s² + 2ζωₙs + ωₙ², ζ ∈ [0.2, 0.78], ωₙ ∈ [1.1, 3.2]. Parameters stay hidden during tuning. The input is always a unit step.

State integration uses RK4 with a 0.002 s step over 24 s. Control: u = Kp(1 − y) + Ki∫(1 − y)dt − Kd y − qTf, with q′ = y − qTf and Tf = 0.06 s. Actuation is limited to ±20. Conditional integration prevents further windup at saturation.

Each challenge generates new targets for overshoot (5–18%), settling time (around max(3, 2τ) seconds for first-order plants or max(3, 5/ωₙ) for second-order plants), and a fixed final-error target of ≈ 0 (≤0.1%), matching the homework’s zero steady-state error requirement; P-only control cannot meet it, so integral action is needed. A final tail is considered settled only if its range over the last second is ≤0.2% of the step. Unsettled or divergent responses cannot pass the final-error test. The score awards equal weight to the three targets; prediction exercises award no extra points.

“Hidden” is an educational feature, not a security boundary: client-side model values can be inspected in developer tools. This is a simulated controller, not Arduino hardware code.
